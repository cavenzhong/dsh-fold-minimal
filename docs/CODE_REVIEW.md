# dsh-fold-minimal 0.4.3：结构与性能排查

2026-11-09，基于 0.4.2（`e683d82`）排查并修复。产品用法见 [README](../README.md)，宿主接口与兼容边界见 [技术说明](TECHNICAL.md)。

## 结论

保留 Host 空入口、单文件浏览器 bundle、无构建和零额外运行时依赖的结构。当前主要成本来自事件触发后的重复测量、过宽的状态订阅与组件关闭后的常驻资源；单纯拆文件不会降低这些成本，反而需要给宿主 ModuleLoader 增加加载或构建步骤。

本次在现有结构内收敛了组件生命周期、修正异步清理、精简失效路径，保留面板排序、More 菜单与跨区拖放的既有交互。未加入新的运行时依赖，也未改变持久化键与数据格式，升级后保留原有偏好。

## 已修复

| 问题 | 原因与影响 | 调整 |
|---|---|---|
| 拖拽收起在停用后仍可能执行 | `pointerup` 排队的动画帧未保存和取消；窗口失焦也没有回收当前拖动 | 取消待执行帧，增加失焦清理与已卸载检查 |
| 高频指针事件重复测量 | 展开侧栏逐事件更新；工具栏同时在事件和下一帧更新 | 两处都只保留最新坐标，每帧最多执行一次拖动测量；松手独立计算最终落点 |
| 重复布局引发写入与通知 | store 的大部分动作无条件创建快照、持久化并通知全部订阅者 | 比较字段和数组内容，无变化时保留原引用并直接返回 |
| 排序默认关闭仍有开销 | 两个排序控制器在 `apply` 时无条件安装监听和插入提示节点 | 抽取 `watchLayoutFlag`，开启才安装，关闭或卸载立即清理 |
| 图标订阅整个布局 | 拖动、二级区开关和排序变化都会改变图标读取的快照 | 影子图标仅选择自身的隐藏布尔值，不因无关 store 字段变化触发更新 |
| 存储降级仍可能抛错 | `document.cookie` / `window.localStorage` 属性读取发生在 `try` 外 | 属性读取与读写操作一并保护；cookie 不可用时尝试镜像，两者都不可用仍保持内存功能 |
| 账本异常回退结构不一致 | 原始条目读取失败返回数组，后续却按 `{ winners, order }` 访问 | 显式返回失败，保留当前影子，下次对账可恢复 |
| 特定面板 id 被误判 | 普通对象字典把 `constructor` / `toString` / `__proto__` 与继承属性混淆 | id 索引使用无原型对象，覆盖顺序、显隐与影子账本 |
| 顺序变化签名存在碰撞 | `order.join(',')` 不能区分本身含逗号的 id | store 去重保留数组引用后，直接比较开关与顺序引用 |
| More 监听重复查 DOM | 全局 pointerover/out 即使菜单关闭也查询浮层 | 菜单关闭时短路；打开后复用仍连接的浮层引用 |

## 冗余清理

- 删除已无运行时调用的 `preview` / `setPreview`，移除影子行写 CSS `order` 的旧路径，统一为「插入线提示、松手提交」。
- 删除仅被增删、从未消费的 `wrappers` 平行数组与未使用的 `ChevronRightIcon`。
- `closestMarked` 直接调用原生 `closest`，移除每层祖先重新向上搜索的循环。
- 工具栏、More 动作与拖动安装复用同一个开关生命周期函数；展开态只订阅一次 `activePanelId`。

## 验证

- `pnpm test`：40 项测试通过（原 32 项，新增 8 项），覆盖纯逻辑、真实 `apply` 注册链路、指针委托、存储受限、影子重注册与卸载。
- `node --check client.js`、`git diff --check` 通过。
- 本地 Chrome 夹具复用已安装 DSH 的 React / ReactDOM、PanelRow、PanelMoreMenu 与工作区提示样式，19 项交互检查通过：展开二级区、悬停菜单互斥、隐藏项打开、主区拖入与恢复、折叠工具栏两区排序/拖放、空分区恢复、无效落点、Esc 取消、后续点击、浅深主题与原生箭头提示。

### 可复现的计数结果

以下是固定操作的计数验证，不是完整宿主窗口的帧率或 CPU 基准：

| 操作 | 0.4.2 | 0.4.3 |
|---|---|---|
| 连续提交 100 次相同布局 | 100 次通知、100 次 cookie 写入、100 次 localStorage 写入 | 0 次通知、0 次 cookie 写入、0 次 localStorage 写入 |
| 同一帧内 100 次 pointermove | 每次立即测量（工具栏另排下一帧测量） | 每个控制器合并为 1 次更新，使用最后坐标 |
| 排序关闭时的排序控制器 | 2 个 pointerdown 监听、2 个插入提示节点 | 不安装 |
| 两个组件均关闭时的拖拽监听 | 排序控制器仍常驻 | 无拖拽监听 |

测试里的帧调度与存储替身分别验证计数及清理，不依赖执行机器的速度。浏览器夹具用于检查真实布局与事件顺序。

## 保留的边界

- 仍依赖 DSH 的槽位优先级语义以及侧栏 DOM 标记，宿主升级时需要回归。
- 对宿主侧栏子树的 MutationObserver 用于恢复被宿主重渲染移除的增强节点；本次没有改成轮询，也没有声称消除全部 DOM 查询。
- 少量面板下的顺序合并和落点排序保留现有直观实现；没有为理论上的大规模面板集合加入复杂缓存。
- 自动验证覆盖 Node 测试和真实组件夹具；未连接完整 DSH 工作窗口，不能据此宣称全应用实测或帧率提升。
