# v0.6.5 重构与适配排查

2026-11-12，基于 `6d11cb8` 检查源码拆分、DSH 0.2.2 适配、固定状态同步和四处拖动落点。

本轮代码审查及自动验证未发现必须推翻当前结构的 P0/P1 问题。发现并修复了以下交互和兼容性问题；浏览器检查使用独立夹具，不能代替完整 DSH 工作窗口验收。

## 修复与补充

| 问题 | 原因与处理 |
|---|---|
| 插入线穿过被拖动项 | 原算法先移除被拖项，再平均两侧坐标；界面中的原行仍占位，中点因此落在行内。四处落点统一调用 `insertionTargetAt`：先确定真实视觉边界，再换算提交下标。覆盖首项、中间项、末项、唯一项和跨区拖入。 |
| 展开侧栏多出跟随图标 | 移除 `installPanelDrag` 的 ghost 路径；只有顶部折叠工具栏及其「更多」拖动保留 ghost。 |
| 下拉菜单混淆固定溢出项与未固定项 | 固定溢出项放在前组；未固定项单列为「未固定到侧栏」，混合列表之间增加分割线。各组沿用保存顺序。仅有未固定项时保留说明，省略顶部空分割线。 |
| 官方菜单外松手仍提交排序 | 预览检测了菜单边界，提交却只看纵坐标。现在预览和提交共用同一落区检测；菜单外松手取消。该控制器补齐 darwin 与已有拖动检查。 |
| 固定状态依赖旧 DOM | 原 observer 只绑定初始侧栏根节点，根被替换后会失联；按标签反推也无法区分同名面板。现在从同一官方注入结果取得 `hooks.entryPins` 和 `setPinned`，直接订阅官方未固定列表，并在面板增删时重算。DOM 只作为能力缺失时的兼容路径，跟随根替换并正确处理空固定列表。 |
| 官方拒绝变更后仍执行跨区排序 | 官方 `plugins` 入口不能取消固定，动作正常返回不代表状态已改变。提交后核对官方快照，拒绝或异常时取消跨区排序。 |
| 插件二级区被识别为宿主行 | 为适配新版 `.panelEntry` 而放宽祖先判定后，旧版 nav 内的插件二级区也可能命中，影子图标会隐藏整块 tray。显式排除插件二级区、工具栏和菜单。 |
| 开发版本号误判 | 无法解析的版本比较原先返回 0，被当成达到新版门槛；带 build metadata 的旧版也会受影响。版本兜底先验证格式，支持 metadata，未知版本继续按能力探测判断。 |

## 结构与冗余

- 保留 `src/` 分块与零依赖单文件构建；发布形态和现有持久化格式适合这个插件，不需要新增打包框架或运行时依赖。
- 合并四份插入位置算法，菜单三组复用同一行渲染函数；移除未使用的文案 ref/参数、跨文件悬空注释和过时说明。
- 固定状态以宿主源为准，排序共用一个 layout store；展开行、原生菜单和折叠工具栏保留各自控制器，表达不同的落区语义。
- 仍有两处宿主耦合需要升级时回归：影子注册依赖 slot 同 id 的优先级语义；官方状态源依赖 `shell.leading` 注入结构。能力缺失时有兼容路径，但 DOM 标签反推无法可靠区分同名菜单，不应作为主路径。
- fragment 共享一个 factory 闭包，主要收益是可读性；函数名和跨文件依赖仍需人工约束。此次没有将它描述成独立模块隔离。
